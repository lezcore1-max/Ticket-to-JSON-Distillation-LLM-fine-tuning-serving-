# Ticket-to-JSON Distillation

Distilling a large LLM ("teacher") into a small fine-tuned open model that turns raw
customer-support messages into structured JSON, then serving it in production.

```text
Input:  "my order #4521 hasn't arrived, it's been 10 days, very frustrated"
Output: {"intent": "track_order", "category": "order", "urgency": "high",
         "product": null, "order_id": "4521", "sentiment": "negative"}
```

**Pipeline:** Bitext messages → teacher LLM labels (Gemini, schema-validated) → QLoRA fine-tune of
Qwen2.5-1.5B-Instruct (Unsloth) → vLLM + FastAPI (Docker, load-tested) → GGUF + Gradio demo.

> 🚧 Work in progress: a 7-day build. Days 1–6 (data, labeling, reviewed test set, evaluation, QLoRA fine-tuning, DistilBERT baseline, vLLM + FastAPI serving, GGUF export, Gradio demo, cost / 1K) are done.

## Output schema

Defined in [`labeling/schema.json`](labeling/schema.json); the same validator
([`labeling/validate.py`](labeling/validate.py)) is used for labeling, evaluation and serving.

| Field | Type | Values |
|---|---|---|
| `intent` | enum | 27 intents (Bitext taxonomy, see [`labeling/taxonomy.json`](labeling/taxonomy.json)) |
| `category` | enum | 11 categories; must match the intent |
| `urgency` | enum | `low`, `medium`, `high` |
| `product` | string or null | named item / plan / account tier, e.g. `"gold account"` |
| `order_id` | string or null | as written, without a leading `#` |
| `sentiment` | enum | `negative`, `neutral`, `positive` |

## Data

Source: [Bitext customer-support dataset](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset)
(synthetic, with deliberate typos and colloquial phrasing). Prepared by
[`labeling/prepare_data.py`](labeling/prepare_data.py) (stats in
[`data/prepared/stats.json`](data/prepared/stats.json)):

1. 26,872 raw messages → **24,025** after removing duplicate templates (placeholders treated as equal).
2. Stratified sample of **3,500** across 27 intents.
3. Split **3,000 train / 300 val / 200 test** *before* labeling. A shared guard
   ([`labeling/splits.py`](labeling/splits.py)) fails if any test id, text or template appears in train/val.
4. `{{placeholders}}` filled with realistic values. Injected order numbers (#940252, ORD-40917, …)
   and account tiers serve as known ground truth for checking the teacher.

## Labeling

[`labeling/label.py`](labeling/label.py) sends 20 numbered messages per request to the teacher
(fits the Gemini free tier: about 175 requests for 3,500 messages). Gemini's structured-output
mode is used with the schema, and every label is checked on its own. Missing or invalid labels
are resent in smaller batches. Runs are resumable and cap their request count.
[`labeling/pilot_report.py`](labeling/pilot_report.py) compares teacher labels against Bitext
labels and injected values, and compares two teachers against each other.

**Teacher:** `gemini-3.5-flash-lite` (free tier), prompt v3 ([`labeling/prompt.md`](labeling/prompt.md)).
The prompt was revised twice after checking samples: v2 added two-step urgency rules; v3 aligned
intent boundaries with Bitext (an order number means `track_order`; using a tier means `switch_account`).

Full-run quality, from [`labeling/label_stats.py`](labeling/label_stats.py)
([report](labeling/label_report.md)):

| | train | val | test |
|---|---|---|---|
| valid labels | 3000/3000 | 300/300 | 200/200 |
| intent = Bitext label | 97.0% | 98.3% | 95.5% |
| order_id = injected id | 321/321 | 33/33 | 22/22 |
| order_id false alarms | 0/2679 | 0/267 | 0/178 |
| urgency low / medium / high | 1311 / 1521 / 168 | 128 / 154 / 18 | 90 / 94 / 16 |

## Test set review

The 200 test labels were reviewed row by row against the written labeling rules
([`labeling/make_review_sheet.py`](labeling/make_review_sheet.py) →
[`data/review/test_review.csv`](data/review/test_review.csv) →
[`labeling/merge_review.py`](labeling/merge_review.py)).

**Reviewer: Claude (an AI model), not a human.** Every test row is marked
`label_source: "claude_checked"`. A human re-check can replace it later with
`merge_review --reviewer human`.

From [`data/final/review_stats.json`](data/final/review_stats.json): 18/200 rows corrected
(teacher exact match 91.0%). Teacher field accuracy against the reviewed labels: intent 95.5%,
urgency 96.0%, product 99.5%, order_id 100%, sentiment 99.0%. Most corrections were urgency
borderline cases and near-miss intents (e.g. `get_invoice` vs `check_invoice`).

**Known limitations of the data:** Bitext messages are synthetic requests, so there is **no
positive sentiment** (in practice sentiment is negative vs neutral), and **high urgency is rare**
(about 6–8%). Evaluation reports these classes separately.

## How to run

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
cp .env.example .env              # add GEMINI_API_KEY

python -m labeling.prepare_data                                   # build splits
python -m labeling.label --list-models                            # see available model ids
python -m labeling.label --split train --n 50 --stratify --out data/labeled/pilot.jsonl
python -m labeling.pilot_report --labels data/labeled/pilot.jsonl --out labeling/pilot_report.md

python -m labeling.label --split train          # also: --split val, --split test
python -m labeling.label_stats                  # quality report for the full run
python -m labeling.make_review_sheet            # test-set review sheet (CSV)
python -m labeling.merge_review --reviewer human  # after reviewing -> data/final/

# Day 4: QLoRA fine-tuning & DistilBERT baseline (after installing GPU deps from requirements-gpu.txt)
python -m training.train_qlora --run-name run1 --batch-size 8 --grad-accum 2
python -m training.eval_qlora --checkpoints-dir training/checkpoints/run1 --pick-best --val-batch-size 32
python -m training.eval_qlora --adapter training/checkpoints/run1/checkpoint-376 --split test --out eval/predictions/qwen_ft_run1.jsonl
python -m eval.eval --pred eval/predictions/qwen_ft_run1.jsonl --name "Small model, fine-tuned (run 1)"

python -m training.train_distilbert
python -m eval.eval --pred eval/predictions/distilbert.jsonl --name "DistilBERT (categorical fields)"

# Day 5: Merge LoRA weights, serve via vLLM + FastAPI (Docker), and load-test with Locust
python -m serving.merge_model --local-files-only
docker compose -f serving/docker-compose.yml up -d --build
python -m serving.eval_api --out eval/predictions/vllm_guided.jsonl
python -m eval.eval --pred eval/predictions/vllm_guided.jsonl --name "Small model, vLLM + guided JSON"
locust -f serving/locustfile.py --host http://localhost:8080 --headless -u 10 -r 5 -t 60s --csv serving/loadtest

# Day 6: Export Q4_K_M GGUF, evaluate on CPU, compute cost/1K, and launch Gradio demo
python -m demo.export_gguf
python -m demo.eval_gguf --server-url http://localhost:8081
python -m eval.eval --pred eval/predictions/gguf_q4_k_m.jsonl --name "Small model, GGUF Q4_K_M (CPU)"
python -m eval.compute_cost
python -m eval.make_table
python -m demo.app
```
